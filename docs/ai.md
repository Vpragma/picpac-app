# ИИ в PicPac App

Состояние на 12.11.2026, ~14:00 (ветка `night-day`: D1 fix1, D6, дорожки ED и SRV).

Коротко:

- ИИ нужен, чтобы клиенту было проще: приложение само видит тёмные, пересвеченные и размытые фото, мягко исправляет явно плохие и меняет фото по команде словами («сделай ярче», «чуть теплее», «убери солнце»).
- **Почти всё работает на устройстве.** Анализ, автоулучшение, команды словарём, «убери солнце», выделение касанием, «Размыть фон», «Осветлить», «Затемнить», ластик и резкость для печати выполняются в браузере; нейросети (SlimSAM, MI-GAN, ESRGAN-slim) загружаются с нашего сайта (их можно скачать заранее кнопкой «Скачать ИИ заранее», 57 МБ).
- **В облако (Cloudflare Workers AI) уходит только у вошедшего клиента и только после его согласия**, и только в двух случаях: (1) команду не понял словарь — на сервер уходит **текст команды**, его разбирает `gpt-oss-120b` в правки редактора; (2) «убери машину» без выделения — уходит **кадр, уменьшенный до 768 точек без EXIF и GPS, и слово-цель** для поиска предмета (Moondream). Гостю и без согласия — ничего, редактор отвечает подсказкой.
- **Оригинал всегда цел:** правки хранятся параметрами, любую можно отменить, «Вернуть оригинал» работает всегда. Изменённые фото помечены значками «Улучшено» и «ИИ».
- **ИИ ничего не решает про людей.** Лица не распознаём и не сравниваем.
- Квоты облака: 20 облачных запросов в сутки на пользователя, общий бюджет около 8 000 «нейронов» в сутки, 10 запросов в минуту, тайм-аут 30 с; каждый вызов — в журнале (без фото и без текста команды). **Поиск предмета (Moondream) на Cloudflare 12.11 отвечает пустым результатом** — редактор просит коснуться предмета, дальше работает выделение касанием. Подробно — раздел 5.

| Автоулучшение явно плохих фото (выключатель «Улучшать автоматически» в редакторе и профиле) | устройство | экспозиция, светлые и тени, баланс белого, контраст (`lib/photo/adjust.js`) | нет |

| «Размыть фон», «Осветлить», «Затемнить» выделенное (кнопки и команды «размой фон», «осветли выделенное») | устройство | маска + чистые функции `lib/photo/mask.js` (те же в превью и печати) | нет |
| «Убрать» выделенное — ластик; «убери X» словом: выделенное убирается, если ничего не выделено — просьба коснуться предмета | устройство, Web Worker | MI-GAN (`public/models/migan`), вклейка только внутри маски с мягким краем (`lib/photo/erase.js`) | нет |
| «Резкость для печати ×2» для фото с «Мало точек» (≤ 1500 точек, нужен WebGL) | устройство, Web Worker | UpscalerJS `esrgan-slim` ×2 (`public/models/upscaler/x2`, `lib/photo/upscale.worker.js`) | нет; увеличенный файл уходит только как печатная версия |
| Печатная версия: при заказе каждое изменённое фото собирается в полном разрешении со всеми правками | устройство, Web Worker | `lib/photo/print.js` | да — готовый файл уходит **в наше хранилище** Supabase (приватный бакет `photos`) рядом с оригиналом, как и само фото |
| Первичная проверка фото для модерации: при загрузке фото в аккаунт — оценки «откровенное / sexy / нейтральное» | устройство, Web Worker | nsfwjs, MobileNetV2 (`public/models/nsfw/`, `lib/photo/nsfw.js`); флаг «нужен модератор» ставит сервер по оценкам: porn + hentai > 0,7 или sexy > 0,85 | на наш сервер уходят только пять чисел-оценок, само фото классификатору никуда не отправляется |

Пока нет: поиск предмета по слову без касания — облачная модель отвечает пустым результатом, поэтому «убери машину» просит коснуться машины (раздел 5).

## 2. Модели и лицензии

Модели на устройстве лежат на нашем сайте (`public/models`, `public/ort`; выделение и ластик вместе с wasm — ≈ 57 МБ, резкость ×2 — 0,9 МБ, nsfwjs — 2,6 МБ; каждый файл меньше 50 МБ; список, источники и лицензии — `public/models/README.md`). Выделение, ластик и резкость загружаются только по нажатию («Выделить касанием», «Убрать», «Резкость для печати») или заранее кнопкой «Скачать ИИ заранее» и кэшируются сервис-воркером; nsfwjs — при первой загрузке фото в аккаунт. `@huggingface/transformers`, `onnxruntime-web`, `@tensorflow/tfjs` и `nsfwjs` попадают только в код воркеров, главная и каталог их не загружают. Лицензии библиотек — в [licenses.md](licenses.md).

Модели (лицензии весов проверены по карточкам моделей, подробнее — [licenses.md](licenses.md), раздел «Модели»):

| MI-GAN (`migan_pipeline_v2.onnx`) — **работает** | MIT (код и веса) | устройство | ластик |

## 4. Хранение и удаление

- Оригиналы и печатные версии — в закрытом бакете `photos`. Правки — параметрами в проекте, а не новыми файлами. Печатная версия собирается заново на устройстве, в ней нет EXIF и GPS.
- `DELETE /api/v1/me/photos` удаляет фото и печатные версии; `DELETE /api/v1/me` удаляет аккаунт, проекты и файлы, заказы обезличивает. Фото заказов, которые уже в работе, удаляются по запросу (`data_requests`), а не мгновенно.
- `GET /api/v1/me/export` — все свои данные одним файлом.
- Выход из аккаунта стирает с устройства черновики, фото и правки (`lib/device.js`).

## 5. Облако Cloudflare Workers AI (D6)

**Сделано (12.11.2026, ветка `night-day-d6`):** таблицы `ai_cloud_consents`, `ai_cloud_usage`, `ai_cloud_budget` и функции квоты (миграция 0011); маршруты `GET /api/v1/ai/cloud`, `POST|DELETE /api/v1/ai/consent`, `POST /api/v1/ai/command` (gpt-oss-120b, только операции редактора, строгая проверка zod), `POST /api/v1/ai/detect` (Moondream, рамки). Каждый вызов: вход → 10 запросов в минуту → схема → согласие → квота (20 в сутки на пользователя, 8 000 нейронов в сутки на приложение) → вызов с тайм-аутом 30 с → запись `ai.cloud_*` в журнал (модель, байты, нейроны, время — без фото и текста). Кадр уменьшается в браузере до 768 точек, сервер ещё раз вырезает из JPEG EXIF, GPS и комментарии.

**Честно:** (1) Moondream на Cloudflare 12.11.2026 отвечал пустым результатом на любые задачи (6 живых вызовов) — поиск по слову отвечает «недоступен», редактор просит коснуться предмета; (2) в редакторе: команду, которую не понял словарь, вошедший клиент с согласием отправляет облаку (результат — те же правки света, цвета и выделения); «убери X» без выделения ищет X облаком, при любом отказе — «Коснитесь того, что убрать»; гостю — подсказка, запросов в облако нет. Лицензия Moondream — не MIT/Apache (Moondream Model License 1.0, коммерческое встраивание разрешено) — решение человека.

## 6. Ограничения и честные оговорки

- **Пороги анализа подобраны на «Тестовой галерее» (20 фото).** На реальных фото возможны ложные значки, например «Темно» у ночных сцен. Анализ идёт по уменьшенной копии 512 точек.
- **Автоулучшение** только мягкое: полностью белые участки не восстановить, сильную размытость не исправить — об этом предупреждаем, в том числе на шаге «Проверка».
- **«Убери солнце» — эвристика, не нейросеть.** Ищет самое яркое небольшое круглое пятно. Хорошо работает на фото «Закат» из тестовой галереи. На фото без солнца (например, белые стены замков) может найти «солнце» там, где его нет, и испортить участок — тогда «Отменить» возвращает фото. На месте большого солнца остаётся мягкое пятно ровного цвета. На ночной улице «солнцем» окажется самый яркий фонарь.
- **Команды словами — словарь.** Покрыты частые формы, включая «наоборот» («поменьше», «слишком жёлтое»). Некоторые формы с отрицанием («X не надо», «перебор с …») понимаются неверно или не понимаются. Непонятная фраза получает ответ «Не понял … Попробуйте: …».
- **Выделение касанием тяжёлое:** кодировщику SlimSAM нужно около 2 ГБ памяти и 10–20 с на компьютере (на телефоне дольше, не измеряли). На телефоне с памятью меньше 4 ГБ или без WebAssembly SIMD выделение честно выключено. «Отмена» останавливает расчёт сразу.
- **Ластик** хорошо убирает небольшие предметы на траве, ковре, небе; на сложной текстуре остаётся мягкое пятно. Большие предметы лучше убирать по частям.
- **Резкость для печати** — только с WebGL и для фото до 1500 точек; без WebGL кнопка отвечает честным отказом (на процессоре это минуты). Чудес нет: детали не появляются, края становятся чётче.
- **Облако — только вошедшим и с согласием.** Поиск предмета по слову (Moondream) 12.11 отвечает пустым — «убери машину» просит коснуться машины; разбор свободных команд (gpt-oss-120b) работает.
- **Печатная версия** собирается при «Подтвердить заказ» по одному фото; на книге с сотней изменённых фото это может занять минуты (на кнопке виден ход: «Готовим фото к печати: 1 из N»).
- Измерения скорости делались на MacBook Pro 2017 (Intel, без GPU, Chrome 111). На реальных телефонах время не измеряли.

## 7. Как проверено

- `npm run test:unit`: разбор команд (`tests/unit/photo-commands.test.mjs`, фразы из отчётов проверяющего, включая «наоборот» и команды для выделенного), анализатор на тестовых фото (`photo-analyze.test.mjs`), «убери солнце» (`photo-local.test.mjs`), маски (`photo-mask.test.mjs`: сжатие без потерь, вне маски ни один пиксель не меняется, превью и печать совпадают, вырезка и дыра ластика, dpi ×2).
- `npm run e2e`: `e2e/editor.spec.mjs` — значки, автоулучшение и его отмена, команды, «До / после», правки после перезагрузки; `e2e/editor-sync.spec.mjs` — правки переходят на другое устройство через аккаунт.
- `e2e/editor-mask.spec.mjs` (телефон и компьютер): касание собаки → «Размыть фон», касание мяча → «Убрать», «убери машину» без выделения, «Резкость ×2», заказ → печатная версия скачивается и проверяется по пикселям (полный размер, фон размыт, мяча нет, собака как в оригинале). С видимым окном Chrome (есть WebGL) — ещё и печатная версия ×2.
- Печатная версия — API-тесты (`npm run test:api`, в том числе «ровно ×2 только с правкой `upscale: 2`»).
- Что в браузерный код не попали ключи — `npm run security:scan`.

Сами убедиться, что фото не уходят в сторонние сервисы: откройте инструменты разработчика → «Сеть», сделайте правку в редакторе — запросов к внешним ИИ-сервисам нет; у гостя нет вообще никаких запросов с фото.

# ИИ в PicPac App

Состояние на 12.11.2026 (ветка `night`, тег `night-s11`).

Коротко:

- ИИ нужен, чтобы клиенту было проще: приложение само видит тёмные, пересвеченные и размытые фото, мягко исправляет явно плохие и меняет фото по команде словами («сделай ярче», «чуть теплее», «убери солнце»).
- **Сейчас всё работает на устройстве.** Анализ, автоулучшение, команды и «убери солнце» выполняются в браузере. **В облако сейчас ничего не уходит**: в коде нет ни одного вызова внешнего ИИ-сервиса, нейросети на устройстве тоже не используются — только обычные алгоритмы обработки изображений.
- **Оригинал всегда цел:** правки хранятся параметрами, любую можно отменить, «Вернуть оригинал» работает всегда. Изменённые фото помечены значками «Улучшено» и «ИИ».
- **ИИ ничего не решает про людей.** Лица не распознаём и не сравниваем.
- Облачная часть (Cloudflare Workers AI) и нейросети на устройстве — **план** (раздел 5). Для него заранее описано, какие данные уйдут в облако, где они обрабатываются и как хранятся — это рекомендация ТЗ 7.4 для внешних AI-API.

## 1. Что работает сейчас

| Функция | Где | Чем | Данные покидают устройство? |
|---|---|---|---|
| Анализ качества каждого фото: яркость, пересвет, тени, контраст, оттенок, резкость, шум, точек на дюйм для печати, дубли | устройство, Web Worker | обычные алгоритмы (`lib/photo/analyze.js`), нейросети нет | нет |
| Значки на миниатюрах: «Темно», «Пересвет», «Размыто», «Мало точек для печати», «Дубль», «Улучшено», «ИИ» | устройство | по результатам анализа | нет |
| Автоулучшение явно плохих фото (выключатель «Улучшать автоматически» в редакторе и профиле) | устройство | экспозиция, светлые и тени, баланс белого, контраст (`lib/photo/adjust.js`) | нет |
| Ручные ползунки: Яркость, Контраст, Тепло, Насыщенность, Светлые, Тени | устройство | та же функция `applyEdits` | нет |
| Команды словами («ярче», «чуть теплее», «поменьше яркости», «слишком жёлтое», «яркость +30», «отмени», «верни оригинал») | устройство | словарь с синонимами, усилителями и отрицаниями (`lib/photo/commands.js`) | нет |
| «Убери солнце», «убери блики» | устройство | поиск самой яркой небольшой круглой области и заливка цветами вокруг (`lib/photo/local.js`), без нейросети | нет |
| «До / после»: ползунок и удержание | устройство | canvas | нет |
| Печатная версия: при заказе каждое изменённое фото собирается в полном разрешении со всеми правками | устройство, Web Worker | `lib/photo/print.js` | да — готовый файл уходит **в наше хранилище** Supabase (приватный бакет `photos`) рядом с оригиналом, как и само фото |

Распознаются, но пока не выполняются (приложение честно отвечает, что функция появится позже): «размыть фон», «убрать предмет» по слову, выделение касанием.

## 3. Какие данные уходят наружу сейчас

| Что | Куда | Зачем |
|---|---|---|
| Оригиналы фото и печатные версии (только у вошедшего клиента) | наш проект Supabase, приватный бакет `photos`, загрузка и просмотр по подписанным ссылкам сервера (просмотр — 10 минут) | синхронизация проекта и печать заказа |
| Параметры правок (`edits`: числа ползунков, `{ kind: "heal", cx, cy, r }` для «убери солнце») | наша база, проект клиента | правки на другом устройстве и в заказе |
| Обезличенные события ИИ-правок (`ai_edit`: автоулучшение или команда, без текста команды и без фото) | наша база, `analytics_events` | метрика «доля проектов с ИИ-правками» на дашборде |

В сторонние ИИ-сервисы (Cloudflare и любые другие) сейчас **не уходит ничего**. Ключи `CLOUDFLARE_*` заведены в окружении на будущее, код их не читает.

## 4. Хранение и удаление

- Оригиналы и печатные версии — в закрытом бакете `photos`. Правки — параметрами в проекте, а не новыми файлами. Печатная версия собирается заново на устройстве, в ней нет EXIF и GPS.
- `DELETE /api/v1/me/photos` удаляет фото и печатные версии; `DELETE /api/v1/me` удаляет аккаунт, проекты и файлы, заказы обезличивает. Фото заказов, которые уже в работе, удаляются по запросу (`data_requests`), а не мгновенно.
- `GET /api/v1/me/export` — все свои данные одним файлом.
- Выход из аккаунта стирает с устройства черновики, фото и правки (`lib/device.js`).

## 5. План: облако Cloudflare Workers AI

Не реализовано. Так мы собираемся сделать облачную часть и вот что заранее известно о данных (по документации Cloudflare, сверено 12.11.2026: developers.cloudflare.com/workers-ai/platform/data-usage/, /platform/pricing/, /platform/limits/).

| Вопрос | Ответ |
|---|---|
| **Провайдер** | Cloudflare, Inc. (США), сервис Workers AI. Модели созданы третьими сторонами (OpenAI, Black Forest Labs, Moondream) |
| **Как вызывать** | Только с нашего сервера: `POST https://api.cloudflare.com/client/v4/accounts/{ACCOUNT_ID}/ai/run/@cf/<модель>`, ключ — в переменных окружения сервера, в браузер не попадает. Без AI Gateway (его логи и кэш не нужны), без R2, KV и других хранилищ |
| **Что передавать** | Команда — только текст фразы. Поиск предмета — кадр, уменьшенный до 768 точек, и слово-цель. Правка — вырезка вокруг выделенной области до 512×512 и текст задания; результат вклеивается на устройстве только внутри области |
| **Чего не передавать** | Фото в полном разрешении, EXIF и GPS, имя файла, id пользователя, проекта и заказа, почту, телефон, адрес |
| **Что всё же может быть в кадре** | Люди, лица, дети, обстановка дома — поэтому только по согласию |
| **Регион** | Cloudflare не называет страну обработки Workers AI: запрос исполняется в его дата-центре, возможно за пределами Беларуси. Для пилота — договор и правовая оценка трансграничной передачи ([pilot-plan.md](pilot-plan.md)) |
| **Хранение у Cloudflare** | По странице «Data usage» у Workers AI — «zero data retention»: содержимое запроса и ответа не хранится после обработки и не используется для обучения. Это заявление провайдера, а не наш аудит |
| **Согласие** | Один раз, только для вошедшего клиента, проверка на сервере. Черновик текста: «Для этой правки на серверы Cloudflare (США) отправится ваша команда и небольшая часть фото, до 512 точек. Cloudflare обещает не хранить эти данные. Остальные правки работают на телефоне и ничего не отправляют. Согласие можно отозвать в профиле» |
| **Лимиты** | 20 облачных правок в сутки на пользователя, общий дневной бюджет около 8 000 «нейронов» (бесплатно Cloudflare даёт 10 000 в сутки), тайм-аут 30 с, запрос меньше 4 МБ (предел Vercel). Когда бюджет исчерпан — «Лимит облачных правок на сегодня исчерпан, правки на телефоне работают» |
| **Журнал** | Запись в `audit_log`: кто, когда, действие, модель, размер в байтах, расход; без изображений и без текста команды |

## 6. Ограничения и честные оговорки

- **Пороги анализа подобраны на «Тестовой галерее» (20 фото).** На реальных фото возможны ложные значки, например «Темно» у ночных сцен. Анализ идёт по уменьшенной копии 512 точек.
- **Автоулучшение** только мягкое: полностью белые участки не восстановить, сильную размытость не исправить — об этом предупреждаем, в том числе на шаге «Проверка».
- **«Убери солнце» — эвристика, не нейросеть.** Ищет самое яркое небольшое круглое пятно. Хорошо работает на фото «Закат» из тестовой галереи. На фото без солнца (например, белые стены замков) может найти «солнце» там, где его нет, и испортить участок — тогда «Отменить» возвращает фото. На месте большого солнца остаётся мягкое пятно ровного цвета. На ночной улице «солнцем» окажется самый яркий фонарь.
- **Команды словами — словарь.** Покрыты частые формы, включая «наоборот» («поменьше», «слишком жёлтое»). Некоторые формы с отрицанием («X не надо», «перебор с …») понимаются неверно или не понимаются. Непонятная фраза получает ответ «Не понял … Попробуйте: …».
- **Нет выделения касанием, ластика, «Размыть фон», резкости для печати и облачных правок** (раздел 5).
- **Печатная версия** собирается при «Подтвердить заказ» по одному фото; на книге с сотней изменённых фото это может занять минуты (на кнопке виден ход: «Готовим фото к печати: 1 из N»).
- Измерения скорости делались на MacBook Pro 2017 (Intel, без GPU, Chrome 111). На реальных телефонах время не измеряли.

## 7. Как проверено

- `npm run test:unit`: разбор команд (`tests/unit/photo-commands.test.mjs`, фразы из отчётов проверяющего, включая «наоборот»), анализатор на тестовых фото (`photo-analyze.test.mjs`), «убери солнце» (`photo-local.test.mjs`).
- `npm run e2e`: `e2e/editor.spec.mjs` — значки, автоулучшение и его отмена, команды, «До / после», правки после перезагрузки; `e2e/editor-sync.spec.mjs` — правки переходят на другое устройство через аккаунт.
- Печатная версия — API-тесты (`npm run test:api`).
- Что в браузерный код не попали ключи — `npm run security:scan`.

Сами убедиться, что фото не уходят в сторонние сервисы: откройте инструменты разработчика → «Сеть», сделайте правку в редакторе — запросов к внешним ИИ-сервисам нет; у гостя нет вообще никаких запросов с фото.

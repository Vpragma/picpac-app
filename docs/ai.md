# ИИ в PicPac App

Состояние на 13.11.2026 (ночь 2, трек N3 «ИИ-редактор полностью локальный», ветка `night2-n3-local-ai`).

Коротко:

- ИИ нужен, чтобы клиенту было проще: приложение само видит тёмные, пересвеченные и размытые фото, мягко исправляет явно плохие и меняет фото по просьбе словами («сделай ярче», «тёплый вечер», «как в старом кино», «убери машину», «размой собаку»).
- **Всё на устройстве, облака нет** (требование жюри). Во время работы редактора ни фото, ни текст команд, ни что-либо о содержимом фото не уходит с телефона. Облачный ИИ (Cloudflare Workers AI: `gpt-oss-120b`, Moondream) удалён вместе с маршрутами, карточкой согласия и квотами.
- Нейросети загружаются **с нашего сайта** (`public/models`, `public/ort`), сервис-воркер их кэширует: после первой загрузки (или кнопки «Скачать ИИ заранее») редактор работает **без интернета** — в редакторе видно «Работает без интернета».
- В наше хранилище фото попадают только при сохранении проекта в аккаунте и при заказе — для печати. И тогда без EXIF и GPS (ориентация сначала переносится в пиксели).
- **Оригинал всегда цел:** правки хранятся параметрами, любую можно отменить, «Вернуть оригинал» работает всегда. Изменённые фото помечены значками «Улучшено» и «ИИ».
- **ИИ ничего не решает про людей.** Лица не распознаём и не сравниваем; детектор знает только «человек» как предмет на кадре.

## 1. Что работает

| Функция | Чем | Данные покидают устройство? |
|---|---|---|
| Анализ качества каждого фото: яркость, пересвет, тени, контраст, оттенок, резкость, шум, точек на дюйм, дубли | обычные алгоритмы в воркере (`lib/photo/analyze.js`) | нет |
| Автоулучшение явно плохих фото (выключатель «Улучшать автоматически») | экспозиция, светлые и тени, баланс белого, контраст (`lib/photo/adjust.js`) | нет |
| Ползунки: Яркость, Контраст, Тепло, Насыщенность, Светлые, Тени | та же функция `applyEdits` | нет |
| Команды словами: синонимы, разговорные формы («фото тёмное», «поконтрастнее», «темновато»), опечатки («ярчи», «контраз побольше», «сабаку размой»), падежи, «наоборот», числа («яркость +30») | словарь `lib/photo/commands.js`; опечатки — расстояние Дамерау — Левенштейна до слов словаря | нет |
| Стили-пресеты: «ч/б», «нуар», «сепия», «винтаж», «как в старом кино», «старое фото», «тёплый вечер», «осеннее», «зимнее», «весеннее», «ярко, как летом», «нежно», «драматично», «как в кино», «сочно»; «верни цвет» — убрать стиль | пресет = сдвиги ползунков + стиль `edits.look { mono, sepia, fade }` (ч/б, сепия, «выцветание»), одинаково в превью и печати | нет |
| Фразы вне словаря («пусть светится», «как на морозе», «как в портретном режиме») | rubert-tiny (MIT, int8 12 МБ) в своём воркере (`lib/photo/meaning.worker.js`): вектор фразы → ближайший смысл из 25 (`lib/photo/intents.js`, векторы примеров посчитаны заранее). Уверенно — выполняет сразу, иначе — 3 кнопки с похожими командами, совсем мимо — подсказка с примерами | нет |
| Поиск предмета словом: «убери машину», «размой собаку», «осветли человека справа», «затемни кота», «размой фон вокруг собаки», «найди кошку» | YOLOX-Nano (Apache-2.0) в воркере выделения → рамка → SlimSAM по рамке → маска → та же правка, что после касания. Словарь «русское слово (все падежи) → класс COCO»: 80 классов (`lib/photo/objects.js`), «слева/справа/в центре/большую/маленькую», «всех» | нет |
| Выделение касанием: касание — «это предмет», «− Убрать часть» | SlimSAM (`public/models/slimsam-77-uniform-boxes`) через `@huggingface/transformers` + onnxruntime-web (wasm из `public/ort`) | нет |
| «Размыть фон», «Размыть» (сам предмет), «Осветлить», «Затемнить» выделенное | маска + чистые функции `lib/photo/mask.js` (те же в превью и печати) | нет |
| «Убрать» — ластик | MI-GAN (`public/models/migan`), вклейка только внутри маски с мягким краем | нет |
| «Убери солнце», «убери блики» | эвристика без нейросети (`lib/photo/local.js`) | нет |
| «Резкость для печати ×2» для фото с «Мало точек» | UpscalerJS `esrgan-slim` ×2 (нужен WebGL) | нет; увеличенный файл уходит только как печатная версия |
| Печатная версия при заказе: оригинал в полном разрешении со всеми правками | воркер `lib/photo/print.worker.js` | да — готовый JPEG без EXIF уходит **в наше хранилище** (приватный бакет `photos`) |
| Первичная проверка фото для модерации при загрузке в аккаунт | nsfwjs (MobileNetV2) в воркере | на наш сервер — только пять чисел-оценок |

Если предмета на фото нет («убери машину» на фото с собакой) — «Не нашёл машину на этом фото. Коснитесь того, что убрать…», и редактор переходит в выделение касанием. Если слово не из словаря предметов («убери гирлянду») — просьба коснуться и список того, что редактор находит сам.

## 2. Модели и лицензии

| Модель | Лицензия | Размер | Когда загружается | Зачем |
|---|---|---|---|---|
| SlimSAM-77 (`slimsam-77-uniform-boxes`, int8) | Apache-2.0 | 13,6 МБ | «Выделить касанием», поиск словом | выделение по касанию и по рамке |
| MI-GAN (`migan_pipeline_v2.onnx`) | MIT | 28 МБ | «Убрать» | ластик |
| YOLOX-Nano (`yolox_nano.onnx`, официальный релиз Megvii 0.1.1rc0) | Apache-2.0 | 3,7 МБ | первая команда с предметом | поиск предмета словом |
| rubert-tiny (`onnx-community/rubert-tiny-ONNX`, int8; в граф добавлен выход скрытого состояния) | MIT | 12,9 МБ с токенами | первая фраза, которую не понял словарь | подбор команды по смыслу |
| ESRGAN-slim ×2 (UpscalerJS) | MIT | 0,9 МБ | «Резкость для печати» | резкость ×2 |
| nsfwjs (MobileNetV2) | MIT | 2,6 МБ | загрузка фото в аккаунт | флаг «пусть посмотрит модератор» |
| onnxruntime-web (wasm) | MIT | 14,8 МБ | вместе с первой моделью | среда выполнения |

Все файлы меньше 50 МБ, лежат в репозитории и отдаются с нашего сайта; `env.allowRemoteModels = false` (transformers.js не ходит на Hugging Face), wasm — из `/ort/`. Не используем: YOLOv5/v8/11 (AGPL-3.0), облачные модели. Источники, ревизии и SHA-256 — [licenses.md](licenses.md), раздел 2, и `public/models/README.md`.

Почему rubert-tiny, а не rubert-tiny2: у rubert-tiny2 нет готового ONNX от авторов или onnx-community, а сторонняя выгрузка — 116 МБ без квантования (больше лимита 95 МБ на файл). У готового `onnx-community/rubert-tiny-ONNX` наружу выведены только logits головы MLM, поэтому скриптом `scripts/onnx-add-output.mjs` в список выходов графа дописан существующий тензор последнего слоя (вектор [CLS], как советует автор модели); веса и узлы не менялись.

## 3. Какие данные уходят наружу

| Что | Куда | Когда |
|---|---|---|
| Оригиналы фото — **без EXIF, GPS, XMP, комментариев и встроенных превью** (ориентация перенесена в пиксели; `lib/photo/stripMeta.js`) | наш проект Supabase, приватный бакет `photos` | только у вошедшего клиента: сохранение проекта в аккаунте |
| Печатные версии (собраны на устройстве, без EXIF) | там же | при оформлении заказа |
| Параметры правок (`edits`: числа ползунков, стиль `look`, маски выделения ≤ 320 точек) | наша база, проект клиента | правки на другом устройстве и в заказе |
| Обезличенные события `ai_edit` (`{ kind: "command" | "local" | "auto" }` — без текста команды, без фото и без сведений о содержимом) | наша база, `analytics_events` | метрика «доля проектов с ИИ-правками» |
| Оценки nsfwjs (пять чисел) | наша база, `project_photos.nsfw` | загрузка фото в аккаунт |

В сторонние сервисы не уходит ничего: CSP страниц разрешает браузеру соединения (`connect-src`) только со своим сайтом и хранилищем Supabase проекта, у воркеров ИИ — только со своим сайтом. На превью-сборках Vercel дополнительно разрешена его панель (`vercel.live`) — на основном сайте её нет.

## 4. Хранение и удаление

- Оригиналы и печатные версии — в закрытом бакете `photos`. Правки — параметрами в проекте, а не новыми файлами.
- `DELETE /api/v1/me/photos` удаляет фото и печатные версии; `DELETE /api/v1/me` удаляет аккаунт, проекты и файлы, заказы обезличивает.
- `GET /api/v1/me/export` — все свои данные одним файлом.
- Выход из аккаунта стирает с устройства черновики, фото и правки (`lib/device.js`).
- Таблицы облачного ИИ (`ai_cloud_consents`, `ai_cloud_usage`, `ai_cloud_budget`, миграция 0011) остались в базе (таблицы не удаляем), приложение их больше не использует; подписи старых записей журнала `ai.cloud_*` сохранены, чтобы журнал читался.

## 5. Доказательства (автотесты)

- `e2e/editor-local-ai.spec.mjs`, тест «редактор не отправляет фото» (гость, телефон и компьютер): автоулучшение, команды и опечатки, стили, фраза вне словаря (модель по смыслу), поиск словом + ластик («убери мяч»), выделение касанием + «Размыть фон», «осветли собаку», «убери машину» (нет на фото), «Резкость ×2», «В корзину». Перехватываются **все** запросы страницы, воркеров и сервис-воркера; тест падает, если хоть один ушёл на другой хост, несёт байты JPEG/PNG/WebP, base64, `data:image`, multipart с `image/*`, тело больше 64 КБ, текст команд или имя файла. Разрешены только события аналитики с полями `type`, `step`, `durationMs`, `props.kind/product/count`. Ещё: CSP `connect-src` без сторонних хостов, «В корзину» ничего не пишет в буфер обмена.
- Тот же файл, тест «авиарежим»: «Скачать ИИ заранее» → «Работает без интернета» → сеть выключена → стили, фраза по смыслу, «размой собаку», «найди кошку» + «Затемнить», ластик по касанию работают.
- `tests/unit/photo-phrases.test.mjs`: 118 фраз → ожидаемая правка, точность печатается (порог 90 %). `tests/unit/photo-meaning.test.mjs`: 30 перефразировок вне словаря — словарь против словаря с моделью. `tests/unit/strip-meta.test.mjs`: EXIF/GPS/XMP/комментарий/хвост убраны, кадр не перекодирован. `tests/unit/photo-commands.test.mjs`, `photo-mask.test.mjs` — как раньше.

Самому убедиться: инструменты разработчика → «Сеть», правки в редакторе — запросов наружу нет (только модели с нашего сайта при первом использовании).

## 6. Ограничения и честные оговорки

- **Точность словаря 100 % на 118 фразах** — набор писался вместе со словарём, это «точность на своих». Обобщение показывают перефразировки вне словаря: словарь понимает 10 %, с моделью по смыслу верная команда выполняется сразу или стоит среди трёх кнопок намного чаще (числа — в отчёте трека и в выводе теста). Пороги модели подобраны на тех же 30 фразах.
- **Поиск словом** знает 80 классов COCO. Небо, лицо, дом, дерево, гирлянду — только касанием. YOLOX-Nano маленький: мелкие и далёкие предметы может не найти, иногда путает (цветы на тестовом фото он считает зонтом); зубра называет коровой — поэтому «зубр» ищется среди коров, медведей и лошадей.
- **Выделение тяжёлое:** кодировщику SlimSAM нужно около 2 ГБ памяти и 10–20 с на компьютере. На телефоне с памятью меньше 4 ГБ выделение выключено; поиск словом там делает правку по овалу внутри найденной рамки (без «Убрать»).
- **Ластик** хорошо убирает небольшие предметы на траве, ковре, небе; большие — лучше по частям.
- **«Убери солнце» — эвристика**, может найти «солнце» на белой стене; «Отменить» возвращает фото.
- **Автоулучшение** только мягкое; пороги анализа подобраны на тестовой галерее (20 фото).
- **Резкость для печати** — только с WebGL и для фото до 1500 точек.
- Скорость мерили на MacBook Pro 2017 (Intel, без GPU): YOLOX ≈ 0,15 с на кадр, rubert-tiny — доли секунды на фразу, SlimSAM 10–20 с на фото. На реальных телефонах время не измеряли.

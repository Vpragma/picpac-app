# ИИ в PicPac App

Состояние на 13.11.2026 (ночь 2, трек N3 «ИИ-редактор полностью локальный», ветка `night2-n3-local-ai`).

Коротко:

- ИИ нужен, чтобы клиенту было проще: приложение само видит тёмные, пересвеченные и размытые фото, мягко исправляет явно плохие и меняет фото по просьбе словами («сделай ярче», «тёплый вечер», «как в старом кино», «убери машину», «размой собаку»).
- **Всё на устройстве, облака нет** (требование жюри). Во время работы редактора ни фото, ни текст команд, ни что-либо о содержимом фото не уходит с телефона. Облачный ИИ (Cloudflare Workers AI: `gpt-oss-120b`, Moondream) удалён вместе с маршрутами, карточкой согласия и квотами.
- Нейросети загружаются **с нашего сайта** (`public/models`, `public/ort`), сервис-воркер их кэширует: после первой загрузки (или кнопки «Скачать ИИ заранее») редактор работает **без интернета** — в редакторе видно «Работает без интернета».
- **Где лежат сами фото.** У гостя — только на устройстве, к нам они попадут с заказом. У вошедшего клиента оригиналы сразу после добавления уходят в его аккаунт PicPac (наше закрытое хранилище): так проект есть на всех его устройствах и готов к печати. Всегда без EXIF и GPS (ориентация сначала переносится в пиксели).
- **Местные правки — только на устройстве** (N7): маски выделения (силуэт предмета), ластик, «убери солнце» с координатами в аккаунт не синхронизируются. В аккаунт уходят только общие параметры правок (числа ползунков, автоулучшение, стиль, «Резкость ×2») и число местных правок. Печатная версия собирается на устройстве со всеми правками — в печать уходит готовый файл.
- **Оригинал всегда цел:** правки хранятся параметрами, любую можно отменить, «Вернуть оригинал» работает всегда. Изменённые фото помечены значками «Улучшено» и «ИИ».
- **ИИ ничего не решает про людей.** Лица не распознаём и не сравниваем; детектор знает только «человек» как предмет на кадре.

## 1. Что работает

| Функция | Чем | Данные покидают устройство? |
|---|---|---|
| Анализ качества каждого фото: яркость, пересвет, тени, контраст, оттенок, резкость, шум, точек на дюйм, дубли | обычные алгоритмы в воркере (`lib/photo/analyze.js`) | нет |
| Автоулучшение явно плохих фото (выключатель «Улучшать автоматически») | экспозиция, светлые и тени, баланс белого, контраст (`lib/photo/adjust.js`) | нет |
| Ползунки: Яркость, Контраст, Тепло, Насыщенность, Светлые, Тени | та же функция `applyEdits` | нет |
| Команды словами: синонимы, разговорные формы («фото тёмное», «поконтрастнее», «темновато»), опечатки («ярчи», «контраз побольше», «сабаку размой»), падежи, «наоборот», числа («яркость +30») | словарь `lib/photo/commands.js`; опечатки — расстояние Дамерау — Левенштейна до слов словаря | нет |
| Стили-пресеты: «ч/б», «нуар», «сепия», «винтаж», «как в старом кино», «старое фото», «тёплый вечер», «осеннее», «зимнее», «весеннее», «ярко, как летом», «нежно», «драматично», «как в кино», «сочно»; «верни цвет» — убрать стиль | пресет = сдвиги ползунков + стиль `edits.look { mono, sepia, fade }` (ч/б, сепия, «выцветание»), одинаково в превью и печати | нет |
| Фразы вне словаря («пусть светится», «как на морозе», «как в портретном режиме») | rubert-tiny (MIT, int8 12 МБ) в своём воркере (`lib/photo/meaning.worker.js`): вектор фразы → ближайший смысл из 25 (`lib/photo/intents.js`, векторы примеров посчитаны заранее). Уверенно — выполняет сразу, иначе — 3 кнопки с похожими командами, совсем мимо — подсказка с примерами | нет |
| Поиск предмета словом: «убери машину», «размой собаку», «осветли человека справа», «затемни кота», «размой фон вокруг собаки», «найди кошку» | YOLOX-Nano (Apache-2.0) в воркере выделения → рамка → SlimSAM по рамке → маска → та же правка, что после касания. Словарь «русское слово (все падежи) → класс COCO»: 80 классов (`lib/photo/objects.js`), «слева/справа/в центре/большую/маленькую», «всех» | нет |
| Выделение касанием: касание — «это предмет», «− Убрать часть» | SlimSAM (`public/models/slimsam-77-uniform-boxes`) через `@huggingface/transformers` + onnxruntime-web (wasm из `public/ort`) | нет |
| «Размыть фон», «Размыть» (сам предмет), «Осветлить», «Затемнить» выделенное | маска + чистые функции `lib/photo/mask.js` (те же в превью и печати) | нет |
| «Убрать» — ластик | MI-GAN (`public/models/migan`), вклейка только внутри маски с мягким краем | нет |
| «Убери солнце», «убери блики» | эвристика без нейросети (`lib/photo/local.js`) | нет |
| «Резкость для печати ×2» для фото с «Мало точек» | UpscalerJS `esrgan-slim` ×2 (нужен WebGL) | нет; увеличенный файл уходит только как печатная версия |
| Печатная версия при заказе: оригинал в полном разрешении со всеми правками, включая местные (маски, ластик, «убери солнце») | воркер `lib/photo/print.worker.js` | да — готовый JPEG без EXIF уходит **в наше хранилище** (приватный бакет `photos`); маски и координаты правок — нет |
| Модерация (N4): при загрузке фото в аккаунт — быстрая проверка на устройстве, перед заказом — повторная на нашем сервере; модератор видит вывод словами | классификатор обнажённости Marqo ViT-tiny + CLIP ViT-B/32 (`public/models/moderation`, `lib/photo/nsfw.worker.js`, `lib/server/moderationCheck.js`) — на устройстве (Web Worker) и на нашем сервере (функция Vercel), раздел 7 | с устройства — только числа-оценки; сервер проверяет файл, который и так лежит в нашем хранилище для печати; сторонних сервисов нет |

Если предмета на фото нет («убери машину» на фото с собакой) — «Не нашёл машину на этом фото. Коснитесь того, что убрать…», и редактор переходит в выделение касанием. Если слово не из словаря предметов («убери гирлянду») — просьба коснуться и список того, что редактор находит сам.

## 2. Модели и лицензии

| Модель | Лицензия | Размер | Когда загружается | Зачем |
|---|---|---|---|---|
| SlimSAM-77 (`slimsam-77-uniform-boxes`, int8) | Apache-2.0 | 13,6 МБ | «Выделить касанием», поиск словом | выделение по касанию и по рамке |
| MI-GAN (`migan_pipeline_v2.onnx`) | MIT | 28 МБ | «Убрать» | ластик |
| YOLOX-Nano (`yolox_nano.onnx`, официальный релиз Megvii 0.1.1rc0) | Apache-2.0 | 3,7 МБ | первая команда с предметом | поиск предмета словом |
| rubert-tiny (`onnx-community/rubert-tiny-ONNX`, int8; в граф добавлен выход скрытого состояния) | MIT | 12,9 МБ с токенами | первая фраза, которую не понял словарь | подбор команды по смыслу |
| ESRGAN-slim ×2 (UpscalerJS) | MIT | 0,9 МБ | «Резкость для печати» | резкость ×2 |
| Marqo nsfw-image-detection-384 (ViT-tiny, `moderation/nsfw-384.onnx`; N4) | Apache-2.0 | 22,4 МБ | первая загрузка фото в аккаунт; на нашем сервере — при проверке | модерация: обнажённость |
| CLIP ViT-B/32 (визуальный энкодер int8 `moderation/clip-vision-b32-int8.onnx`, нулевой выстрел; N4) | MIT | 89,1 МБ | первая загрузка фото в аккаунт (в режиме экономии трафика и на мобильном интернете — нет); на нашем сервере — при проверке | модерация: символика, оружие, кровь, наркотики |
| nsfwjs (MobileNetV2) — с N4 не используется, файлы оставлены | MIT | 2,6 МБ | — | — |
| onnxruntime-web (wasm) | MIT | 14,8 МБ | вместе с первой моделью | среда выполнения |

Все файлы меньше 95 МБ (больше 50 МБ — только CLIP, 89,1 МБ), лежат в репозитории и отдаются с нашего сайта; `env.allowRemoteModels = false` (transformers.js не ходит на Hugging Face), wasm — из `/ort/`. Не используем: YOLOv5/v8/11 (AGPL-3.0), облачные модели. Источники, ревизии и SHA-256 — [licenses.md](licenses.md), раздел 2, и `public/models/README.md`.

Почему rubert-tiny, а не rubert-tiny2: у rubert-tiny2 нет готового ONNX от авторов или onnx-community, а сторонняя выгрузка — 116 МБ без квантования (больше лимита 95 МБ на файл). У готового `onnx-community/rubert-tiny-ONNX` наружу выведены только logits головы MLM, поэтому скриптом `scripts/onnx-add-output.mjs` в список выходов графа дописан существующий тензор последнего слоя (вектор [CLS], как советует автор модели); веса и узлы не менялись.

## 3. Какие данные уходят наружу

| Что | Куда | Когда |
|---|---|---|
| Оригиналы фото — **без EXIF, GPS, XMP, комментариев и встроенных превью** (ориентация перенесена в пиксели; `lib/photo/stripMeta.js`) | наш проект Supabase, приватный бакет `photos` (аккаунт клиента) | у вошедшего клиента — сразу после добавления фото (автосохранение проекта в аккаунт); у гостя — только с заказом, после входа |
| Печатные версии (собраны на устройстве со всеми правками, без EXIF) | там же | при оформлении заказа |
| Общие параметры правок (`edits`: автоулучшение и ползунки — числа, стиль `look`, `upscale: 2`, `by`) и **число** местных правок (`local`) | наша база, проект клиента (`options.settings.edits`) и фото (`project_photos.edits`) | автосохранение проекта и заказ — чтобы правки были на другом устройстве и в печати |
| **Не уходит:** маски выделения (`edits.masks`, силуэт предмета в RLE), сами местные правки (`edits.ops`: «Размыть», «Осветлить», «Затемнить», «Убрать», «убери солнце» с координатами `cx, cy, r`), текст команд, точки касания | — остаётся в проекте на устройстве (IndexedDB) | никогда; на другом устройстве редактор честно пишет: «Правки по выделению к этому фото остались на устройстве, где их сделали» |
| Обезличенные события `ai_edit` (`{ kind: "command" | "local" | "auto" }` — без текста команды, без фото и без сведений о содержимом) | наша база, `analytics_events` | метрика «доля проектов с ИИ-правками» |
| Оценки модерации с устройства (до 10 чисел, N4): быстрый флаг «проверит модератор»; повторную проверку делает сервер (`project_photos.moderation`) | наша база, `project_photos.nsfw` | загрузка фото в аккаунт (только у вошедшего клиента) |

Отбор делает функция `serverEdits()` (`lib/photo/edits.js`) — её вызывают синхронизация проекта (`lib/sync.js`) и сохранение печатной версии (`lib/photo/print.js`); сервер повторяет тот же отбор (`withoutLocalEdits`, `photoEditsForServer` в `lib/server/projects.js`), если старая версия приложения из кэша телефона пришлёт маски. Если печатная версия фото с местными правками не собралась (обрыв сети), заказ не оформляется — «Повторить»: печатать «параметрами» такие правки нельзя, их на сервере нет.

В сторонние сервисы не уходит ничего: CSP страниц разрешает браузеру соединения (`connect-src`) только со своим сайтом и хранилищем Supabase проекта, у воркеров ИИ — только со своим сайтом. На превью-сборках Vercel дополнительно разрешена его панель (`vercel.live`) — на основном сайте её нет.

## 4. Хранение и удаление

- Оригиналы и печатные версии — в закрытом бакете `photos`. Правки — параметрами в проекте, а не новыми файлами.
- `DELETE /api/v1/me/photos` удаляет фото и печатные версии; `DELETE /api/v1/me` удаляет аккаунт, проекты и файлы, заказы обезличивает.
- `GET /api/v1/me/export` — все свои данные одним файлом.
- Выход из аккаунта стирает с устройства черновики, фото и правки (`lib/device.js`).
- Таблицы облачного ИИ (`ai_cloud_consents`, `ai_cloud_usage`, `ai_cloud_budget`, миграция 0011) остались в базе (таблицы не удаляем), приложение их больше не использует; подписи старых записей журнала `ai.cloud_*` сохранены, чтобы журнал читался.

## 5. Доказательства (автотесты)

- `e2e/editor-local-ai.spec.mjs`, тест «редактор не отправляет фото» (гость, телефон и компьютер): автоулучшение, команды и опечатки, стили, фраза вне словаря (модель по смыслу), поиск словом + ластик («убери мяч»), выделение касанием + «Размыть фон», «осветли собаку», «убери машину» (нет на фото), «Резкость ×2», «В корзину». Перехватываются **все** запросы страницы, воркеров и сервис-воркера; тест падает, если хоть один ушёл на другой хост, несёт байты JPEG/PNG/WebP, base64, `data:image`, multipart с `image/*`, тело больше 64 КБ, текст команд или имя файла. Разрешены только события аналитики с полями `type`, `step`, `durationMs`, `props.kind/product/count`. Ещё: CSP `connect-src` без сторонних хостов, «В корзину» ничего не пишет в буфер обмена.
- Тот же файл, тест «авиарежим»: «Скачать ИИ заранее» → «Работает без интернета» → сеть выключена → стили, фраза по смыслу, «размой собаку», «найди кошку» + «Затемнить», ластик по касанию работают.
- `e2e/editor-sync.spec.mjs`, тест «местные правки остаются на устройстве» (N7, вошедший клиент): «размой собаку» и «убери солнце» → автосохранение в аккаунт → заказ. Ни в одном пишущем запросе (PATCH проекта, печатная версия, заказ, аналитика) нет ключей `rle`, `masks`, `mask`, `ops`, `cx`, `cy`; в аккаунте у фото только `local: 1`; печатная версия в хранилище на месте собаки отличается от оригинала (собака размыта), а в углу кадра — нет. `tests/unit/edits-server.test.mjs` — отбор `serverEdits`; `tests/api/sync.test.mjs` — сервер не хранит маски и координаты, даже если их прислать.
- `tests/unit/photo-phrases.test.mjs`: 118 фраз → ожидаемая правка, точность печатается (порог 90 %). `tests/unit/photo-meaning.test.mjs`: 30 перефразировок вне словаря — словарь против словаря с моделью. `tests/unit/strip-meta.test.mjs`: EXIF/GPS/XMP/комментарий/хвост убраны, кадр не перекодирован. `tests/unit/photo-commands.test.mjs`, `photo-mask.test.mjs` — как раньше.

Самому убедиться: инструменты разработчика → «Сеть», правки в редакторе — запросов наружу нет (только модели с нашего сайта при первом использовании).

## 6. Ограничения и честные оговорки

- **Точность словаря 100 % на 118 фразах** — набор писался вместе со словарём, это «точность на своих». Обобщение показывают перефразировки вне словаря: словарь понимает 10 %, с моделью по смыслу верная команда выполняется сразу или стоит среди трёх кнопок намного чаще (числа — в отчёте трека и в выводе теста). Пороги модели подобраны на тех же 30 фразах.
- **Поиск словом** знает 80 классов COCO. Небо, лицо, дом, дерево, гирлянду — только касанием. YOLOX-Nano маленький: мелкие и далёкие предметы может не найти, иногда путает (цветы на тестовом фото он считает зонтом); зубра называет коровой — поэтому «зубр» ищется среди коров, медведей и лошадей.
- **Выделение тяжёлое:** кодировщику SlimSAM нужно около 2 ГБ памяти и 10–20 с на компьютере. На телефоне с памятью меньше 4 ГБ выделение выключено; поиск словом там делает правку по овалу внутри найденной рамки (без «Убрать»).
- **Ластик** хорошо убирает небольшие предметы на траве, ковре, небе; большие — лучше по частям.
- **«Убери солнце» — эвристика**, может найти «солнце» на белой стене; «Отменить» возвращает фото.
- **Автоулучшение** только мягкое; пороги анализа подобраны на тестовой галерее (20 фото).
- **Резкость для печати** — только с WebGL и для фото до 1500 точек (в «Тестовой галерее» по умолчанию выбрано такое фото — `nesvizh-small.jpg`, 800 точек).
- **Местные правки привязаны к устройству.** Открыли проект на другом телефоне — там общие правки есть, а правок по выделению нет (редактор пишет об этом); чтобы напечатать фото с ними, заказ оформляют с того устройства, где их сделали.
- Скорость мерили на MacBook Pro 2017 (Intel, без GPU): YOLOX ≈ 0,15 с на кадр, rubert-tiny — доли секунды на фразу, SlimSAM 10–20 с на фото. На реальных телефонах время не измеряли.

## 7. Модерация фото (N4)

**Зачем переделали.** Жюри: фото с обнажённой женской грудью не получило флага, а у фото собаки модератор видел «sexy 5 %». Прежний nsfwjs (с N4 не используется) слабый, пороги были высокие, модератор видел сырые проценты.

**Модели** (обе в `public/models/moderation`, лицензии — [licenses.md](licenses.md), раздел 2):

- классификатор обнажённости Marqo `nsfw-image-detection-384` (ViT-tiny, Apache-2.0, 22 МБ): вход 384×384, вероятность «nsfw»;
- CLIP ViT-B/32 (MIT, визуальный энкодер int8, 89 МБ) без дообучения: кадр сравнивается с 39 готовыми текстовыми описаниями классов (`clip-text.json`, считаются один раз скриптом `scripts/moderation-embed.mjs`). Категории: обнажённая грудь, обнажённое тело, сцена сексуального характера, нацистская символика (флаг, свастика, руны СС, орёл, приветствие), оружие, кровь и насилие, наркотики. Остальные классы — «обычные фото» (собака, пляж и купальники, дети, статуя, картина, флаг страны, еда и кухонный нож, толпа, протест, пустой кадр…): без них открытый вопрос «что на фото?» сводился бы к опасным классам.

**Где считается.**

1. На устройстве при загрузке фото в аккаунт — в Web Worker (`lib/photo/nsfw.worker.js`), onnxruntime-web из `public/ort`, модели с нашего сайта, кэш сервис-воркера; в режиме экономии трафика и на мобильном интернете (если браузер это сообщает) — только классификатор (22 МБ). Загрузка фото не ждёт проверку дольше 3 с: оценки досылаются позже (PATCH). На наш сервер уходят только числа. Через 25 и 90 с после загрузки приложение перечитывает флаги фото проекта: если сервер нашёл то, что устройство пропустило, клиент тоже видит «Это фото проверит модератор».
2. На нашем сервере — тот же код и те же модели (`lib/server/moderationEngine.js`: onnxruntime-web в Node, без нативных библиотек; `sharp` уменьшает фото). У вытянутого кадра сервер смотрит CLIP-ом не только центр, но и два квадрата у краёв — для символики, оружия, крови и наркотиков (обнажённость — по центру и целиком классификатором: кусок фото в купальнике у края CLIP путает с грудью). Сервер сам читает из хранилища файл, который пойдёт в печать (печатную версию, если есть): сразу после загрузки — в фоне (`after`), и **обязательно перед созданием заказа** (`checkProjectsBeforeOrder`, до 45 с). Поэтому поддельные «чистые» оценки с устройства ничего не дают — проверено автотестом.
3. Флаг «проверит модератор» только ставится (оценки устройства ИЛИ проверка сервера), автоматика его не снимает и никогда не отклоняет фото. Не успели или не смогли проверить перед заказом — фото тоже уходит модератору («Автоматическая проверка не прошла — посмотрите фото»).

**Пороги** (`lib/moderation.js`, «Возможно … (средняя уверенность)» / «Найдено … (высокая уверенность)»): классификатор 0,45 / 0,75; CLIP-обнажённость (грудь + тело + сцена) 0,3 / 0,6; символика 0,3 / 0,6; оружие, кровь, наркотики 0,35 / 0,7. Если CLIP уверен, что это статуя, картина или пустой однотонный кадр (≥ 0,5), а сам обнажённости не видит, одного классификатора мало: мраморный Давид в музее и бежевая стена не помечаются.

**Что видит модератор:** находки словами и откуда они («по проверке на сервере» / «на телефоне клиента»), фото размыто до «Показать», клиент — только инициалы. У обычных фото без флага проценты не показываются нигде: клиенту API больше не отдаёт оценки, клиент видит только нейтральное «Это фото проверит модератор». В журнал пишутся решение модели (`moderation.auto`: коды находок, без фото) и решение модератора с находками модели (`moderation.approve` / `moderation.return`).

**Ограничения.** Полноту по обнажённости на настоящих фото не измеряли (нет набора). CLIP B/32 слабее на мелких деталях: маленькая свастика на большом снимке может не набрать порога (CLIP видит квадрат 224×224: на устройстве — центр, на сервере — центр и края). Классификатор и CLIP не отличают историческое фото или религиозный символ от пропаганды — поэтому решение всегда за человеком. Карточка OpenAI CLIP называет модель исследовательской: мы проверили её на своём наборе и используем только как подсказку модератору.

# PicPac на ноутбуке, Android и iPhone

PicPac — веб-приложение (PWA): одно и то же приложение открывается в браузере и устанавливается значком на экран.
Магазины приложений (App Store, Google Play) — вне объёма ТЗ (раздел 2). Путь к ним — в конце.

Состояние на 12.11.2026, этап S07. Честно отмечено, что проверено и чем.

## Что есть в приложении

| Возможность | Как сделано |
|---|---|
| Установка значком | Манифест `app/manifest.js` → `/manifest.webmanifest`: «PicPac — фотокниги», `display: standalone`, `start_url` и `scope` — `/`, цвета из токенов (`#faf5ed`), иконки 192, 512, maskable 512, `apple-touch-icon` 180, экраны запуска iOS (7 размеров). Кнопка «Установить приложение» — в профиле (событие `beforeinstallprompt`), на iPhone там же — инструкция |
| Работа без сети | Свой сервис-воркер `public/sw.js`. Оболочка (главная, «Мои книги», редактор, корзина), статика сборки, шрифт, иконки и каталог сохраняются на устройстве. Без сети эти страницы открываются из кэша; остальные — экран «Нет сети — черновики сохранены на устройстве» с переходом в «Мои книги» |
| Черновики | Проекты и фото — в IndexedDB браузера (`lib/draft.js`). Доступны без сети, переживают перезагрузку и закрытие вкладки |
| Очередь загрузки | У вошедшего клиента фото уходят в аккаунт (`lib/sync.js`). Без сети ждут, при появлении сети отправляются сами (событие `online` и повторы через 15 с). Плашка «Нет сети» показывает «Фото загрузятся, когда появится связь: N» |
| Данные пользователя | Ответы API с данными пользователя (вход, корзина, заказы, проекты, фото) сервис-воркер не кэширует никогда. При выходе устройство очищается (`lib/device.js`: IndexedDB, `picpac:*`, пуш-подписка, кэши `picpac-user-*`) |
| Обновление | У кэша есть версия (коммит сборки, `/sw.js?v=…`). Новая версия ждёт: тост «Есть новая версия — Обновить», открытые вкладки не ломаются. Старые кэши удаляются при активации |
| Прямые ссылки | `/orders/{id}`, `/cart`, `/product/{slug}`, `/editor?project={id}` открываются напрямую, в том числе из установленного приложения. Гость на заказе видит «Войти» с возвратом (`/login?next=…`). Проекта нет на устройстве — «Войти» с возвратом в этот проект |

## Ноутбук: macOS и Windows

| Браузер | Установка | Без сети | Пуши |
|---|---|---|---|
| Chrome, Edge | Значок установки в адресной строке или кнопка в профиле. Открывается отдельным окном | Да | Да (этап S09) |
| Safari 17+ (macOS Sonoma) | «Файл → Добавить в Dock» | Да | Да, после добавления в Dock |
| Firefox | Установки PWA нет — работает как сайт | Да | Да |

## Android

- **Chrome:** «Установить приложение» в профиле или меню ⋮ → «Установить». Значок на экране, окно без адресной строки.
- Без сети: оболочка, черновики и каталог открываются; фото ждут сети и загружаются сами.
- **Background Sync** в Chrome есть, но мы его пока не используем: загрузка идёт, пока открыто приложение. Закрытое приложение догрузит фото при следующем открытии.
- Пуши работают и без установки (этап S09).

## iPhone и iPad: Safari

- **Установка:** «Поделиться» (квадрат со стрелкой) → «На экран „Домой“» → «Добавить». Кнопки установки в iOS нет, поэтому в профиле показываем инструкцию. С iOS 16.4 так же можно установить из Chrome и Edge на iPhone.
- **Пуши:** только у приложения, добавленного на экран «Домой», iOS 16.4 и новее. В обычной вкладке Safari пушей нет.
- **Без сети:** работает (сервис-воркер поддерживается с iOS 11.3).
- **Ограничения iOS для PWA:**
  - нет Background Sync: фото догружаются, только пока приложение открыто;
  - нет события `beforeinstallprompt`, установка только вручную;
  - если сайт не открывали 7 дней и он не добавлен на экран «Домой», Safari может удалить его данные, в том числе черновики. После входа проекты хранятся в аккаунте и вернутся;
  - место для данных ограничено; при нехватке iOS может очистить кэш.
- Экран запуска и цвет строки статуса настроены (`appleWebApp` в `app/layout.js`).

## Путь к нативным приложениям (развитие, вне ТЗ)

- **Android — TWA (Trusted Web Activity):** то же PWA в обёртке для Google Play (Bubblewrap). Нужны `assetlinks.json` на сайте и аккаунт разработчика Google Play.
- **iOS и Android — Capacitor:** нативная оболочка над тем же кодом. Даёт пуши через APNs и FCM, фоновую загрузку и доступ к галерее. Нужны аккаунт Apple Developer и проверка App Store.
- Код приложения при этом не переписывается: те же страницы, API и черновики.

# Безопасность PicPac

Как защищены данные и как это проверено. Пункты SEC-01…SEC-24 — из ТЗ и требований команды.
Проверки запускаются командами: `npm run test:api` (API, 60+ сценариев), `npm run test:auth`, `npm run test:mfa`,
`npm run e2e` (Playwright), `npm run security:scan` (секреты и `npm audit`), `npm run test:all` (всё подряд).
Состояние на 12.11.2026 (тег `night-s11`). Открытые замечания независимой проверки — в разделе 7; часть из них исправляется на финальном этапе, итог — в [test-report.md](test-report.md).

## 1. Вход, роли и доступ

| ID | Что сделано | Как проверено |
|---|---|---|
| SEC-01 | Каждый маршрут `/api/v1/*` (кроме каталога, входа и регистрации) проверяет сессию на сервере (`requireUser` в `lib/server/api.js`). Пароли хранит Supabase Auth (bcrypt), в нашем коде и журнале паролей нет, `console.log` с телом запроса нет | `test:api`: гость → 16 закрытых маршрутов → 401 с `requestId`, отказ `proxy.js` — тоже с `requestId` |
| SEC-09 | Роль проверяется дважды: `proxy.js` (первая линия для `/admin` и `/api/v1/admin/*`) и сама страница или обработчик. Роль берётся из базы (`user_roles`), кука выбранной роли подписана и сверяется с ролями пользователя | `test:api`: клиент и модератор → журнал админа 403; `test:auth`: подменённая кука роли → 403 |
| SEC-13 | IDOR: проект, фото, заказ, обращение, печатная версия ищутся только среди своих (`user_id`), чужой объект → 404 (не 403, чтобы не подтверждать существование). Попытки пишутся в журнал (`denied`) | `test:api`: B не видит, не меняет и не удаляет проект A; не фиксирует путь A; не видит и не оплачивает заказ A; не читает обращение A |
| SEC-21 | Двухфакторный вход для сотрудников (TOTP Supabase) включается переменной `REQUIRE_STAFF_MFA=1`; на демо выключен, чтобы жюри могло войти | `npm run test:mfa` |
| SEC-22 | Сессия Supabase: короткий токен доступа (1 ч) и токен обновления; `proxy.js` продлевает сессию на каждом запросе. После удаления аккаунта старые куки не дают доступа к данным (роли удалены → 401/403), но `GET /api/v1/me` со старой кукой до истечения токена ещё отвечает `authenticated: true` с id и почтой (раздел 7). **Долг:** после выхода сессия и токен обновления отозваны, но перехваченный токен доступа работает до своего срока (≤ 1 ч): подпись проверяется локально (`getClaims`). Исправление — проверять сессию на сервере (`getUser` или список отозванных `session_id`), этап S12 | `tests/api/session.test.mjs`: удаление аккаунта → старые куки 401/403 ✅; выход → todo (200) |

## 2. Данные и база

| ID | Что сделано | Как проверено |
|---|---|---|
| SEC-03 | RLS включён на всех таблицах. Публичный ключ (`anon`) не видит ни строк, ни файлов. Клиент — только своё, запись в заказы и статусы — только сервер (секретный ключ, только на сервере) | `test:api` «RLS: публичный ключ не видит ни одной строки и ни одного файла» |
| SEC-05 | Ввод — схемы `zod` на сервере (длины, форматы, перечисления); **лишние поля отклоняются** (`z.strictObject`, ответ 400). Вывод — React (экранирует сам), `dangerouslySetInnerHTML` с данными пользователя нет. Запросы — supabase-js (параметры), без склейки SQL | `test:api`: лишние поля → 400, подменённые цены → 400 и итог считает сервер, `<script>` в продукте → 400 |
| SEC-17 | `DELETE /api/v1/me`: файлы в хранилище, проекты, корзина, адреса, подписки удаляются; заказы обезличиваются (получатель и адрес стираются, `user_id = null`) и остаются для отчётности | `test:api` «удаление аккаунта» |
| SEC-23 | Ограничения: фото в проекте ≤ 500, позиций в корзине ≤ 50, количество 1–99, тексты с предельной длиной (имя 100, сообщение 2000 и т. д.), файл ≤ 25 МБ. **Предел 100 Мп на сервере не проверяется** (раздел 7, п. 1) | схемы `zod`, `test:api` (большой файл, неверные списки) |
| Гонки | «Удалить проект» и «оформить заказ» одновременно: строка проекта удаляется только если он не заказан (`neq status ordered`), файлы — после. Фото: если проект успели заказать, файлы не трогаются (их держит снимок заказа) | `test:api` «гонка удалить проект + оформить заказ» |

**Почта в журнале после удаления аккаунта.** Журнал действий неизменяемый (записи нельзя менять и удалять — так устроена база): он нужен, чтобы разбирать инциденты и спорные заказы. Поэтому почта в старых записях журнала остаётся после удаления аккаунта, а сам аккаунт, проекты, фото и адреса удаляются. Срок хранения журнала в продакшене — 1 год (решение для Фотопринт). Альтернатива — хранить хеш почты — отложена: по почте считается лимит попыток входа.

## 3. Сеть и браузер

| ID | Что сделано | Как проверено |
|---|---|---|
| SEC-04 | Только HTTPS (Vercel: `http://` → 308 на `https://`), `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload` в `next.config.mjs` | `curl -I` на превью |
| SEC-07 | Куки сессии `HttpOnly`, `Secure` (на https), `SameSite=Lax`. CSRF: все изменяющие запросы проверяют заголовок `Origin` (чужой, `null` или похожий хост → 403). Если `Origin` нет, проверяется `Referer` (чужой → 403, S12); запрос без обоих заголовков — не из браузера (у скрипта нет чужих cookies), пропускается. | `test:api`: чужой Origin → 403 `bad_origin` |
| SEC-16 | **Строгая CSP с nonce** (`proxy.js` → `lib/server/csp.js`): новый nonce на каждую страницу, `script-src 'self' 'nonce-…' 'strict-dynamic' 'wasm-unsafe-eval'` (без `unsafe-inline` и `unsafe-eval`), `frame-ancestors 'none'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `worker-src 'self' blob:`, `img-src`/`connect-src` — свой сайт, `data:`, `blob:` и хранилище Supabase. Стили — `'unsafe-inline'` (React пишет атрибуты `style`). Страницы стали динамическими (nonce нельзя вшить в заранее собранную страницу). Ещё: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=()`, `Cross-Origin-Opener-Policy: same-origin` | `curl -I`; руками: каталог, редактор (анализ в воркере, команды, «убери солнце»), загрузка фото в хранилище, корзина и оформление, админка — консоль без нарушений CSP; unit-тест политики |
| SEC-10 | Ошибки без стека: `{ ok:false, error:{ code, message, requestId } }` и заголовок `X-Request-Id`. Неизвестный `/api/…` → JSON 404, неверный метод → JSON 405 с `Allow`, отказы `proxy.js` (401/403) — тоже с `requestId`. `poweredByHeader: false` | `test:api` «единый формат ошибки» |

## 4. Файлы

| ID | Что сделано | Как проверено |
|---|---|---|
| SEC-08 | Только JPEG/PNG: тип и размер (≤ 25 МБ) до выдачи ссылки, проверка первых байтов после загрузки (подделка удаляется), имя файла — uuid, приватный бакет, подписанные ссылки на 10 минут. Печатная версия перекодирована на устройстве (без EXIF и GPS) | `test:api`: GIF и > 25 МБ отклоняются, текст под видом JPEG удаляется |

## 5. Злоупотребления и журнал

| ID | Что сделано | Как проверено |
|---|---|---|
| SEC-06 | **Почти полностью (S12).** Лимиты частоты (`private.rate_limits`, функция `rate_limit_hit`): вход и регистрация (по почте и IP), промокод, загрузка, печатная версия, обращения и сообщения, заказы, выгрузка данных, события аналитики и — с S12 — все остальные изменяющие маршруты (`limitWrite` в `lib/server/api.js`: проекты, фото, порядок, корзина, перенос корзины, тестовая оплата, роль, выход, «Удалить мои фото», профиль). Ответ 429 с понятным текстом и `Retry-After` (у входа и регистрации тоже). Нет «Забыли пароль?» — открыто | `test:api` «больше 20 проверок промокода за минуту → 429»; вход и регистрация — 429 по счётчику попыток (`app/api/v1/auth/login`, `register`) |
| SEC-15 | Журнал: вход и выход, смена роли, проекты, фото, корзина, перенос корзины, заказ, тестовая оплата, обращения, проверки фото, удаление данных и аккаунта, отказы доступа (`denied`), в том числе чтение чужого проекта и перенос чужого проекта в корзину. Отказы гостю пишутся не чаще 10 раз в минуту с одного IP (бот не забьёт журнал); этот счётчик живёт в памяти одного экземпляра сервера, а на Vercel их несколько — предел приблизительный. Экран «Журнал действий» для админа — последние 100 записей, **фильтров нет** (по пользователю, действию, дате) | `test:api` «журнал», «чужой проект и cart.merge → denied» |
| SEC-14 | Маскирование телефона и почты для модератора и оператора — **не сделано** (этап S08) | — |
| SEC-18 | Выход: синхронизация, затем стирание IndexedDB, `picpac:*`, кэша; сессия гасится на сервере | e2e «выход стирает данные устройства» |
| SEC-19 | Пуш-уведомлений пока нет (этап S09) | — |
| SEC-20 | Облачный ИИ (Cloudflare) пока не подключён: всё редактирование — на устройстве; ключ Cloudflare только в окружении сервера | `security:scan`: ключа нет в коде и фронтенде |

## 7. Открытые замечания (независимая проверка S04, 12.11.2026)

Проверяющий работал как атакующий на превью `night-s04`. Прошло: чужие объекты (IDOR) на 10 маршрутах → 404, подмена куки роли → 403, CSRF с чужим, `null` и похожим `Origin` → 403, заголовки и CSP, история git без секретов. Найдено и **на момент `night-s11` не исправлено**:

**Исправлено на S12 (тег `night-s12-fix1`):** п. 1 — предел 100 Мп по заголовку файла на сервере (`POST …/photos` → 400 `too_many_pixels`, файл удаляется) и на устройстве до декодирования (`lib/imageMeta.js`, `lib/draft.js`), API-тест на PNG-«бомбу» 20000×20000; п. 2 (лимиты) — `limitWrite` через `rate_limit_hit` на всех изменяющих маршрутах: создание, изменение и удаление проекта, фиксация и удаление фото, порядок фото, корзина, перенос корзины, тестовая оплата, выбор роли, выход, «Удалить мои фото», имя в профиле (429 с `Retry-After`); п. 3 — `Retry-After` у 429 входа, регистрации, кода MFA и удаления аккаунта; п. 4 — лишние поля входа, регистрации и адреса доставки → 400. SEC-07: если у изменяющего запроса нет `Origin`, проверяется `Referer` (чужой → 403); запрос без обоих заголовков — не из браузера, пропускается. «Забыли пароль?» по-прежнему нет (п. 2, вторая часть) — открыто.
